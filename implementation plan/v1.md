# StudyForge V1 — Complete Implementation Plan

> **Version:** V1
> **Source:** Architect Guideline + Lead Decision Logs
> **Target File:** `studyforgeImplementation/main_app/studyforge_main.html`

---

## Overview

StudyForge is a single-HTML-file web application that transforms study material (uploaded file / typed topic / pasted text) into structured, AI-enriched study notes through an 8-stage pipeline.

**Tech Stack:** React 18 (Babel JSX) + Tailwind CSS + 3 pre-built Gemini AI functions

**AI Functions:**
- `geminiGenerateText(prompt)` -> text/JSON generation and analysis
- `geminiSearchText(query)` -> live web search grounding
- `geminiImageCreation(prompt)` -> base64 image generation

---

## Stage-by-Stage Plan

### STAGE 1 — Input Material (Status: BUILT)

**Purpose:** Collect study material from user. Screen: 1.

**Key Components:**
- ResumeBanner: Shows saved session offer
- FileUploadSection: Drag-drop zone, extracts text/base64
- TopicInputSection: Dynamic sub-topic rows (up to 10), internet toggle, 5-step AI chain
- PasteTextSection: Big textarea with character counter (no hard cap)
- SettingsPanel: 6 dropdowns + CA toggle, starts open

**5-Step AI Chain (Method 2 — Type Topic):**
1. User enters topic + sub-topics
2. AI call 1: geminiGenerateText/geminiSearchText -> expands sub-topic list
3. Approval panel shown — user checks/unchecks each suggested sub-topic
4. AI call 2: geminiGenerateText -> generates full content using final topic list
5. Content fills Section C textarea for user review

**State Fields Produced:**
- fileInfo, fileContent, fileBase64, topic, subTopics, focus, pastedText, inputMethod, settings

---

### STAGE 2 — AI Reading (Status: TODO)

**Purpose:** Run Gemini analysis on input material; show animated progress while working. Screen: 2. AI Calls: 1x geminiGenerateText.

**Behaviour:**
- Screen auto-runs analysis on mount (no button click needed)
- 6 animated progress steps shown to user
- Progress bar fills 0->85% during animations, 100% when AI responds
- On success: auto-navigate to Stage 3
- On failure: show error with "Try Again" button

**Animation Steps:**
1. Detecting input type and language...
2. Extracting readable text content...
3. Identifying subject and context...
4. Analyzing structure and features...
5. Counting elements and topics...
6. Preparing your understanding report...

**AI Response Schema:**
JSON with: subject, subDiscipline, contentType, language, complexity, topics[], definitions[], formulas[], codeBlocks[], pyqs[], geographyMentions[], personalitiesMentioned[], institutionsMentioned[], counts{}, detectedFeatures[], suggestedParts, splitRationale

**State Fields Produced:** analysisData (full AI JSON)

---

### STAGE 3 — Understanding + Feature Detection (Status: TODO)

**Purpose:** Show what AI understood; let user enable/disable feature categories. Screen: 3. AI Calls: 0.

**Layout:**
- Left panel (3/5): Subject card + stats card (9 count tiles) + expandable definitions/formulas table
- Right panel (2/5): Feature toggles by category

**12 Feature Categories (dynamic visibility):**
1. CONTENT_CORE - Always shown (detailed notes, quick revision, definitions...)
2. FORMULAS_MATH - Shown if formulas found or science content
3. GEOGRAPHY - Shown if locations detected
4. PERSONALITIES - Shown if people mentioned
5. DATA_CHARTS - Shown if tables/diagrams found
6. CODE_PROGRAMMING - Shown if code content
7. CURRENT_AFFAIRS - Shown if CA toggle on or psc/history content
8. EXAM_PREP - Shown if UPSC/PSC exam selected
9. STORYTELLING - Always shown
10. ADMINISTRATIVE - Shown if institutions mentioned
11. PROCESS_CREATION - Always shown (collapsible optional)
12. MEDICAL_SCIENCE - Shown if subject includes bio/chemistry/medicine

**State Fields Produced:** features{featureId: true|false}

---

### STAGE 4 — Parts / Structure (Status: TODO)

**Purpose:** AI splits material into logical learning parts; user reviews and edits. Screen: 4. AI Calls: 1x geminiGenerateText.

**Behaviour:**
- Runs partsPrompt on screen mount
- Shows loading spinner while generating
- Renders part cards in 2-column grid
- User can: Edit, Delete, Merge, Add part

**AI Response Schema:**
parts[]: id, title, summary, topics[], complexity, estimatedLength, applicableFeatures[], needsCurrentAffairs, hasFormulas, hasCode, suggestedImageCount, learningObjective
totalParts, splitRationale

**Modals:** EditPartModal (title, summary, topics, CA toggle), AddPartModal, Merge (2 parts -> AI combines)

**State Fields Produced:** parts[]

---

### STAGE 5 — Blueprints (Status: TODO)

**Purpose:** Generate teaching blueprint per part (parallel); user approves each. Screen: 5. AI Calls: N x geminiGenerateText in parallel (Promise.all).

**Behaviour:**
- All blueprints generated simultaneously with Promise.all
- Each card shows loading/done/error independently
- User must approve ALL blueprints before Stage 7
- "Approve All" button + progress bar

**AI Response Schema (per part):**
headings{main, subHeadings[]}, textPlan{fromSource[], willAdd[], containers[]}, imagePlan[], caPlan{needed, searches[]}, validationPlan[], estimatedLength, generationPromptPreview

**State Fields Produced:** blueprints{partId: blueprint}, approvals{partId: true|false}

---

### STAGE 6 — Blueprint Detail Overlay (Status: TODO)

**Purpose:** Full-screen overlay to inspect and edit a single part's blueprint; AI chat to modify. Screen: 6 (overlay). AI Calls: Variable x geminiGenerateText (chat).

**3-Panel Layout:**
- Header: Back button, Part title, Save & Approve button
- Left scroll (70%): Headings Plan, Text Plan, Image Plan, CA Plan, Validation Plan
- Right sticky (30%): AI Chat with minimise button

**Features:**
- All fields directly editable (headings, prompts, CA queries, image prompts)
- Style selector per image (35 VISUAL_STYLES)
- Regenerate Prompt button per image
- Force Enable CA button
- AI chat modifies blueprint JSON then re-renders

**State Fields:** Updates blueprints[partId] + approvals[partId] on Save & Approve

---

### STAGE 7 — Generation Workspace (Status: TODO)

**Purpose:** Generate actual notes per part; manage images, CA, validation, approval. Screen: 7. AI Calls: Per part: 1 text + N images + optional CA + optional validation.

**Layout:**
- Sticky top bar: Generate All | Progress N/Total | Search | Export
- Left sidebar (200px): Part list with status icons
- Main scroll: Part sections stacked vertically

**Per Part Section Contains:**
1. Part header + approval bar
2. ContentSection[] (rendered from generated.sections)
3. ImageCard[] (per blueprint.imagePlan item)
4. CurrentAffairsZone (collapsible, per CA scope)
5. Validate button -> ValidationModal

**All 17 Container Types:**
concept_box, formula_box, code_block, comparison_table, story_box, geography_box, personality_card, pyq_box, quick_revision, definition_box, analogy_box, timeline_box, process_box, institution_box, experiment_box, summary_box, data_insight

**Image Generation Flow:**
idle -> Generate Image button -> geminiImageCreation -> done -> Approve Image
Each card has: Regenerate, style override, Approve buttons

**Current Affairs Zone:**
Scopes: National Recent (2024+), National Major (2020-23), State Recent, State Major
Each: geminiSearchText -> results -> Merge into Notes / Ignore

**Visualize This Feature:**
- mouseup listener detects 15+ char selection
- Floating "Visualize This" button
- VisualizePopup: auto-generates image prompt, style selector (35 styles, mixed mode), generates image, Insert Here

**Approval Bar (Per Part):**
[Approve Text] [Approve Images] [Approve Part] (gated — need both first)
When approved: [Part Approved] [Unlock to Edit]

**AI Validation (Per Part):**
- Returns: overallScore, grade, strengths[], improvements[], missingElements[]
- ValidationModal with action buttons for each improvement

**State Fields Produced:**
generated{partId: {sections[], quickRevision[]}}, partApprovals{partId: {textApproved, imagesApproved, partApproved}}

## Quality Checklist

- Every AI call in try/catch with ErrorModal on failure
- All JSON responses cleaned of markdown wrappers before JSON.parse
- sanitizeInput() on all user-typed prompts before AI call
- sanitizeOutput() on all AI text before dangerouslySetInnerHTML
- All 8 screens reachable and functional
- Session save/restore works with IndexedDB
- fileBase64 NEVER persisted to IndexedDB
- Blueprint generation runs with Promise.all (parallel)
- Image generation is async — text shows immediately
- Loading spinners on every async action
- Dark mode applies to all screens
- Prompt Center shows all 12 prompts, all copyable
- Print CSS works correctly
- No dead buttons — every action has visible feedback

## Known Constraints

- Single file: All CSS, JS, React in one .html file
- API key: Empty apiKey in AI functions — user must insert their Gemini key
- Large files: PDFs with 50K+ chars truncated to 8000 chars in Stage 2 prompt
- Image storage: Base64 images NOT saved to IndexedDB — lost on page refresh
- DOC/DOCX: Browser cannot extract text from binary Word files natively
