# Global Master Constitution: StudyForge Architecture & Platform Mandates

## 1. Executive Mission & Environment Mandates

StudyForge is an autonomous AI Study Material Transformer designed to produce high-yield, structured, exam-grade study notes from any input document, topic, or raw text. The application operates under strict platform constraints to ensure 100% portability, zero-dependency deployment, and uncompromised pedagogical depth.

---

## 2. Core Non-Negotiable Governance Rules

### Rule 1: Zero External Backend & Zero Build Tools
1. The final deployment artifact MUST be a single, monolithic `.html` file containing all necessary structure (HTML), design tokens and styles (CSS), and runtime logic (Vanilla JavaScript).
2. The codebase MUST NOT require Node.js, npm, Webpack, Vite, Babel, or any server-side runtime (Python, FastAPI, Express).
3. The file MUST execute cleanly via standard `file://` protocol or inside the Google Gemini Canvas sandbox environment.
4. No external backend frameworks (LangChain, LangGraph, CrewAI, AutoGen) are permitted. All orchestration, state transitions, tool execution, and guardrail heuristics MUST be implemented in native client-side JavaScript.

### Rule 2: Ambient Canvas Authentication & Direct REST Invocation
1. In accordance with the Gemini Canvas environment specification, all generative AI calls MUST leave `apiKey = ""` as an empty string. The Canvas sandbox intercepts outgoing requests to `generativelanguage.googleapis.com` and automatically injects valid ambient credentials.
2. The UI MUST NOT display API key entry fields, configuration modals, or warning banners requesting manual authentication.
3. The underlying endpoints are locked to:
   - Text & Reasoning: `https://generativelanguage.googleapis.com/v1beta/models/gemini-3-flash-preview:generateContent`
   - Live Web Grounding: Same endpoint with `tools: [{ googleSearch: {} }]`
   - Educational Diagram Generation: `https://generativelanguage.googleapis.com/v1beta/models/imagen-4.0-generate-001:predict`

### Rule 3: Native In-Browser Guardrails & Truncated JSON Resilience
1. Large, reasoning-heavy prompts (especially during deep analysis, blueprints, and multi-part notes) are subject to token boundary cut-offs.
2. The runtime parser MUST implement deterministic quote, string, bracket (`[`), and brace (`{`) balancing. A truncated JSON response MUST be automatically repaired and salvaged rather than throwing an unhandled `SyntaxError` or displaying a failure banner.
3. Every external fetch call MUST be wrapped in a two-attempt automated backoff retry (2s / 4s) before bubbling up an error state.
4. Schema validators must ensure that missing optional fields are safely defaulted to empty arrays or empty strings rather than causing `TypeError: undefined is not iterable`.

### Rule 4: Safe Persistence Architecture (Decoupled IndexedDB & LocalStorage)
1. Browser `localStorage` has a strict quota limit of ~5 MB across origins. Base64 images generated by Imagen 4.0 average 1.2 MB to 2.5 MB each.
2. Storing raw image data URLs in `localStorage` is **STRICTLY FORBIDDEN**.
3. The application MUST maintain an `ImageDB` IndexedDB store for visual assets and binary blobs.
4. `localStorage` is strictly reserved for lightweight text/metadata state (`schemaVersion: 3.0`) and execution history.

### Rule 5: Dynamic Dual-Pass Current Affairs Mandate
1. Every generated part MUST feature up-to-date, verified real-world context relevant to its subject domain.
2. **Pass 1 (Pre-Generation Grounded Swarm)**: Prior to note synthesis, the engine MUST execute parallel, domain-specific Google Search queries covering:
   - Recent Developments, Schemes, and Data (2024–Present).
   - Milestone Background, Amendments, and Reports (2020–2023).
   - Comparative national/global indicators.
3. **Pass 2 (Validator Subagent Verification & Enrichment)**: Following note synthesis, a dedicated validator pass MUST inspect the text for dated claims or statistical gaps, execute targeted follow-up searches if necessary, and inject verified source URLs.

### Rule 6: Multi-Exam PYQ Intelligence Layer
1. The engine MUST include a dedicated Previous Year Question (PYQ) intelligence engine with configurable target exam focus (MPPSC / MP State Exams, UPSC Civil Services, UPPSC, BPSC, and State PSCs).
2. For every generated topic, the notes MUST provide:
   - Historical exam frequency and trend assessment.
   - Real past questions (with Year & Exam code).
   - Official model answer structure (Intro, Core Analytical Points, Diagram/Flowchart, Conclusion).
   - "Examiner Trap" warnings detailing common misconceptions and trick options.

### Rule 7: Self-Explanatory Visual Standards
1. Educational graphics generated by Imagen MUST NOT be decorative or photorealistic. Prompts MUST mandate clean 2D vector layouts, diagrammatic structure, white backgrounds, and high-contrast educational styling.
2. Every visual asset MUST be paired with a mandatory structured explanation container containing:
   - Component Map & Legend (defining every labeled element).
   - Lifecycle / Mechanism Breakdown (detailed step-by-step prose).
   - Exam Takeaway (how to reproduce or interpret in an exam setting).

### Rule 8: 22 Pedagogical Container System Fidelity
1. The UI contains 22 specialized pedagogical container CSS tokens.
2. The AI note writer MUST NOT dump unstructured plain text (`safe_content must be plain text only` is repealed).
3. The renderer MUST parse structured content into rich, distinct pedagogical cards (LaTeX formula derivation cards, case-study narrative boxes, misconception clarifiers, legal/constitutional article cards, and data comparison tables).

### Rule 9: Zero AI Execution During Screen 8 Export
1. The export engine on Screen 8 MUST be 100% deterministic and client-side.
2. Compiles ONLY user-approved parts and sanitized assets.
3. Strictly forbids any runtime AI calls during export compilation.
