### **QA.1 — Confirm the Multi-Step Chain for Method 2**

**Question:** When user types topic "National Income" and sub-topics "GDP, GNP" and clicks AI Draft Text, the following chain was proposed. Is this correct?

- Step 1: User types topic + sub-topics
- Step 2: AI fetches/expands related sub-topics (AI decides what else to cover)
- Step 3: AI generates a prompt for content creation
- Step 4: AI generates the actual content using that prompt
- Step 5: Content flows into Method 3 paste area as if uploaded

**Options:**
- Option A: Confirmed, this is the flow
- Option B: Different — describe

**Lead's Decision:** Option A — Confirmed

**Implementation Approach:**
1. User enters "National Income" with sub-topics "GDP, GNP"
2. First AI call fires: "Given topic National Income with sub-topics GDP, GNP — what other sub-topics are essential for comprehensive coverage?" AI returns expanded list (e.g., adds NDP, NNP, Per Capita Income, HDI, GDP Deflator)
3. Expanded list shown to user for approval/editing (see QA.2)
4. After user approves, second AI call fires with the final topic + sub-topic list to generate full content
5. Generated content appears in Method 3 paste area where user can review and edit before clicking Continue

**Why This Approach:**
- AI knows what sub-topics are needed for comprehensive coverage (user might not know all related topics)
- Two-step process ensures user stays in control (they see what AI wants to add before content is generated)
- Content enters the same pipeline as uploaded files — no separate handling needed downstream
- This is the foundation for the prompt chain: Topic → Expanded Topics → Content Prompt → Content → Image/Text/Search prompts

### **QB.2 — How Many and What Type of Facts Per Location?**

**Question:** When extracting facts about a location, should it always be the same depth, or should it vary?

**Options:**
- Option A: Basic (3-5 facts always)
- Option B: Medium (10-15 facts always)
- Option C: Deep (20+ facts always)
- Option D: AI decides based on how prominently the location appears
- Option E: Your preference

**Lead's Decision:** Context-driven — not a fixed count, varies based on WHY the location appears

**Lead's Exact Words:** "Not every time based on the context. For example if we are learning on Indus Valley Civilization and MP appears then fact related to that topic I want. If it is geopolitics then geographical and political facts I want. If it is in current affairs otherwise not. I mean location is in current affair then we need fact, but now for history it might not be in current affairs but with respect to that content it is required so accordingly create solution."

**Implementation Approach:**

The type and depth of facts extracted depend on WHY the location appears in the content. The AI prompt for location facts is dynamically generated based on context.

**Context Detection Rules:**

| Content Context | What Facts to Extract for "Madhya Pradesh" |
|---|---|
| **Indus Valley Civilization (History)** | Archaeological sites in MP, historical significance in that era, ancient trade routes, cultural artifacts found. NOT: current CM, current GDP, current schemes |
| **Geopolitics / Border Issues** | Borders (5 states), strategic locations, security aspects, political geography, interstate relations |
| **Current Affairs (MP in news)** | Recent CM statements, latest schemes, budget allocation, election data, current controversies, development metrics |
| **Economics (State GDP comparison)** | GSDP data, per capita income, key industries, poverty index, comparison with national average, recent economic policies |
| **Geography (Physical Features)** | Rivers (Narmada, Chambal), mountains, forests, climate zones, mineral resources, connectivity |
| **Passing Mention (not central to topic)** | Basic only: capital (Bhopal), region (Central India), 1-2 relevant facts |

**Dynamic Prompt Template:**
```
Location detected: "Madhya Pradesh"
Content context: This part discusses [Indus Valley Civilization]
Location relevance: [Historical sites mentioned, appears 3 times]

Extract facts about Madhya Pradesh relevant to:
- [Indus Valley Civilization context]
- [Historical significance in this era]
- [Archaeological connections]

DO NOT extract facts about:
- Current politics, current schemes, current GDP
- Facts unrelated to [Indus Valley topic]

Return as JSON: {facts: [...], relevance_to_topic: "..."}
```

**Caching Strategy:**
- Cache key includes BOTH location AND context: `location_facts_MP_indus_valley`
- Different from `location_facts_MP_geopolitics`
- If same location appears in different parts with different contexts, separate fact sets are fetched and cached independently

**Why This Approach:**
- Generic facts waste space and confuse students (why is current CM mentioned in an Indus Valley chapter?)
- Context-driven facts are directly useful for understanding and exam answers
- PSC/UPSC questions ask about locations IN CONTEXT — not random trivia
- Saves tokens by not fetching irrelevant facts

### **QC.1 — When Can AI Suggest New Images During Generation?**

**Question:** At what moments during the generation process can AI suggest that an image is needed?

**Options:**
- Option A: During text generation only (AI inserts IMAGE_NEEDED tags)
- Option B: After text is done (AI reviews and suggests)
- Option C: During validation popup only
- Option D: All three moments
- Option E: Your preference

**Lead's Decision:** Option D — All three moments, using a unified function chain

**Lead's Exact Words:** "All three we will implement a function. If AI thinks that for this text image in this way is required it will call that function along with text. That function first puts that text in the HTML file then calls prompt function to generate image prompt by sharing the content AI shared along with the location where AI told to generate the image and asks prompt function to further call image generator function which will generate image and return back and then first calling function will place that image after the text. If it is generated during validation then AI will find the location in our page to put that image and call that function and provide the position detail as well."

**Implementation Approach — The Function Chain:**

```
STEP 1: AI identifies image need
↓
STEP 2: Call insertImageAtLocation(text, imageDescription, position)
↓
STEP 3: Function places text in HTML at specified position
↓
STEP 4: Function calls generateImagePrompt(imageDescription, surroundingContent, position)
↓
STEP 5: Prompt function creates detailed image prompt
↓
STEP 6: Prompt function calls generateImage(detailedPrompt)
↓
STEP 7: Image generator creates and returns image
↓
STEP 8: Original function places image after the text at specified position
```

**Three Trigger Points Using Same Chain:**

| Moment | How AI Triggers | Position Info |
|---|---|---|
| **During text generation** | AI includes `{image_needed: true, description: "...", after_section: "nominal_gdp"}` in its JSON output | Position = after the section AI just wrote |
| **After text generation (review)** | AI reviews complete text and returns `{missing_images: [{description: "...", position: "after_paragraph_7"}]}` | Position = specific paragraph/section reference |
| **During validation** | Validation AI finds gaps and returns `{suggested_images: [{description: "...", insert_at: "div#part2-section3"}]}` | Position = exact DOM element reference in the page |

**Why This Approach:**
- One function chain handles all three moments (no duplicate code)
- AI provides both the image description AND where to place it
- Works seamlessly whether triggered during writing, review, or validation
- Position detail ensures images land in the right place every time

**Question:** Final consolidated validation checks different things for different subjects (Economics checks metrics, Polity checks judgments, History checks timelines). How should this work?

**Lead's Exact Words:** "See for example GST, it is concept of Economics right, and have Polity as well as Historic timeline needed thing. But yes during prompt generation of blueprint on that time we can check how broader that topic is and we have rough idea like how to visualize the concepts."

**Implementation Approach:**

The validation prompt does NOT use rigid subject categories. Instead:

1. **During blueprint generation:** AI already assessed what the topic contains (formulas, laws, timelines, personalities, etc.)
2. **During final validation:** AI receives the consolidated document with ALL its content types
3. **Validation prompt asks:** "Given this complete document about [topic], check:
   - Are all concepts that need formulas properly formulated?
   - Are all legal/constitutional aspects covered with proper article references?
   - Are all historical aspects covered with proper timelines?
   - Are all comparisons that should exist present?
   - Are all personalities properly covered with relevant facts?
   - Is any important aspect of this topic missing for PSC/UPSC preparation?"
4. AI applies whatever checks are relevant to THAT specific content — not based on a rigid subject label

**Example — GST Topic:**
- AI finds: GST has economic concepts (tax rates, revenue) + polity aspects (constitutional amendment, GST Council powers) + historical timeline (pre-GST tax system, implementation phases)
- Validation checks ALL three aspects — doesn't pick just "Economics rules"
- Reports: "Missing: Timeline of GST implementation phases. Missing: 101st Constitutional Amendment details. Weak: No comparison of pre-GST vs post-GST tax structure."

**Why This Approach:**
- Real topics are cross-domain (GST = Economics + Polity + History)
- Rigid subject rules would miss cross-domain gaps
- Content-driven validation catches everything relevant
- More intelligent — AI looks at what's actually there, not what category label says

**Visualization Guidance (from Lead):**
During blueprint and validation, AI also considers how to visualize:
- Stories → comic style characters
- Case stories → different character comic style showing the case
- Formulas → metrics, graphs, pictographs
- Comparisons → tables, matrices

### **QG.2 — When User Edits Prompt and Regenerates**

- Option C: Your preference

**Lead's Decision:** Option B — AI creates a new prompt using system prompt plus changes needed

**Lead's Exact Words:** "B — AI will create a prompt using system prompt plus changes needed."

**Implementation Approach:**

3. Final prompt sent to AI:
   - System prompt (unchanged base instructions)
   - User's edited content prompt
   - Additional note: "The user modified the original prompt. Key changes: [diff summary]. Generate output aligned with these modifications."
4. This helps AI understand the USER'S INTENT behind the edit, not just the raw text change

**Example:**
- Original prompt: "Create infographic showing GDP formula with 4 branches"

- Diff detected: "Added branches for subsidies and taxes"
- Final prompt includes: "User wants to expand the formula breakdown to include subsidies and taxes as additional branches. Generate accordingly."

**Why This Approach:**
- AI understanding user's intent produces better results than just executing raw text
- The diff summary gives AI context about WHY the prompt changed
- System prompt stays intact (safety)
- Better output quality compared to Option A (which just sends edited text without context)

- Option B: Include full formula from analysis output (structured JSON data, not raw text)

- Option D: Your preference

**Implementation Approach:**
1. Analysis output (from Stage 3) contains ALL formulas in structured format:
```json
{
  "F-001": {"formula": "GDP = C+I+G+NX", "variables": {...}, "page": 10},
  "F-002": {"formula": "GNP = GDP + NFIA", "variables": {...}, "page": 11},
  "F-003": {"formula": "NDP = GDP - Depreciation", "variables": {...}, "page": 15}
}
```
2. When generating Part 2 (which covers formulas F-001 and F-002), the prompt includes F-001 and F-002 data

4. AI uses the structured data to properly reference the formula in Part 2's text
5. AI decides how to present it: full formula with explanation, brief reference with "covered in detail in Part 3," or inline mention

**Why This Approach:**
- Structured JSON is cleaner and smaller than raw text snippets
- AI can interpret structured data better than raw text fragments
- No need to slice raw text from another part's pages
- Analysis output already has everything needed (formula string, variables, page ref)
