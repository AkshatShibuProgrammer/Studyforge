# STUDYFORGE — COMPLETE CONSOLIDATED DOCUMENTATION

## PART 1: PRODUCT OVERVIEW

### Product Name
StudyForge — AI-Powered Study Material Transformer

### One Line Description
An app that takes any study material (file or topic) and transforms it into comprehensive, exam-ready or learning-ready notes with intelligent visuals, current affairs, previous year questions, and subject-adaptive features.

### Who Is It For
- Students preparing for UPSC, State PSC, or any competitive exam
- Students studying academic subjects like Computer Science, Literature, Medicine
- Anyone who wants to deeply understand a topic with visual explanations
- Self-learners who want organized notes from raw material

### How It Works (Simple)
User gives input → App reads and understands → App plans how to teach → App writes notes with images and extras → User reviews and approves → User downloads final document

---

## PART 2: THE THREE STARTING POINTS

### Starting Point A: User Has A File
User uploads study material they already have. Supported file types:
- PDF
- TXT (plain text / notepad files)
- DOC / DOCX (Word documents)
- HTML (web pages saved as files)
- MD (Markdown files)
- Images (JPG, PNG — text extracted from images)

### Starting Point B: User Has A Topic Name
User does not have a file. They just type:
- Main topic name (required)
- Sub-topics (optional, can add multiple up to 10)
- Specific focus area (optional)

App generates comprehensive raw content on that topic and treats it as if it were an uploaded document.

### Starting Point C: User Pastes Text
User copies text from somewhere and pastes it directly into the app.

- Organized notes broken into logical parts
- Visual explanations — diagrams, charts, comics, flowcharts, tables, infographics

- Stories and scenarios to make concepts memorable

- Data insight boxes with chart analysis
- Institution/Administration boxes
- Analogy boxes for concept clarity
- Process/Creation boxes

### Output Formats
- HTML (styled webpage)
- PDF (via browser print)
- Markdown (plain text with formatting)
- Copy to clipboard (formatted text and images)

## PART 6: IMAGE GENERATION PHILOSOPHY

### Not One Style — Mixed Styles
A single image can combine multiple visual styles when the content demands it.

Example: GDP vs GNP image could contain:
- Flowchart showing where GDP and GNP sit in economics hierarchy
- Bar chart comparing India's GDP vs GNP over years
- Table showing data comparison for India and MP
- Small explanation cards on the side describing behavior patterns

### Styles Available (35 Options Grouped)
- Process/Flow: Flowchart, Step-by-Step, Decision Tree, Sankey, Process Map, Timeline, Gantt
- Structure: Entity Diagram, Hierarchical Tree, Network, Sequence Diagram, Use Case, State Machine, Mind Map
- Data: Bar Chart, Pie Chart, Line Graph, Scatter Plot, Heat Map, Radar, Bubble Chart, Stacked Area, Pictograph, Heat-Map Table
- Concept: Concept Map, Venn Diagram, Comparison Matrix, Comic Story, Infographic, 3D Model, Icon Array, Geographic Map, Funnel, Storyboard, Table Diagram

### How Images Are Created
- AI automatically picks the best style(s) based on content
- User can change to any style via dropdown
- AI generates a detailed prompt for image creation
- User can edit the prompt before generation
- User can regenerate with different style
- User can describe their own vision and AI builds the prompt

### Key Image Principles (Lead's Directives)
- Focus on UNDERSTANDING, not aesthetics
- Make tough concepts simple through visuals
- Think like an infographic designer
- Preferred styles: infographics, comic stories, formula breakdowns, metric visualizations, fact cards
- Every image should teach something — viewer should understand the concept just by looking at the image
- Do not make it pretty — make it clear
- AI tries to put as much information as possible in one image
- If combining would make image too cluttered, AI splits into multiple images
- AI decides if multiple images are needed based on data volume

### Interactive Image Creation
User highlights any text in notes → camera button appears → shows editable auto-generated prompt → shows recommended styles → user picks/modifies → image generates → user approves or regenerates

### Image Function Chain (Architectural Decision)
When AI identifies an image is needed at any point:
1. Call insertImageAtLocation(text, imageDescription, position)
2. Function places text in HTML at specified position
3. Function calls generateImagePrompt(imageDescription, surroundingContent, position)
4. Prompt function creates detailed image prompt
5. Prompt function calls generateImage(detailedPrompt)
6. Image generator creates and returns image
7. Original function places image after the text at specified position

This chain works identically whether triggered during text generation, after text review, or during validation.

## PART 7: AI VALIDATION SYSTEM

### Two-Layer Validation

#### Layer 1: Per-Part Validation (When User Approves a Part)
When user clicks "Approve Part" on any part:
1. AI call fires with everything in that part (text + all images + what each image shows)
2. AI creates a summary of that part covering what content was written, what images were created, what each image shows, what sources/enrichments were used
3. AI checks for issues and gaps
4. Popup appears with options: Cross (cancel), Approve Modifications (accept AI suggestions), Ignore (approve as-is)
5. If user clicks "Approve All" master button — this happens one by one for each part sequentially with progress indicator

#### Layer 2: Final Consolidated Validation (After ALL Parts Approved)
Once all parts are approved:
1. AI call fires with consolidated data of ALL approved parts
2. AI checks against content-driven requirements (NOT rigid subject categories)
3. AI reports gaps and suggestions
4. User can accept suggestions (new parts/sections added) OR ignore and export

### Content-Driven Validation (Not Subject-Based)
Validation does NOT use rigid subject categories. Instead:
- AI looks at what content types actually exist (formulas, laws, timelines, personalities)
- AI checks if all content types are properly covered
- Example: GST topic has Economics + Polity + History aspects — AI validates ALL three, not just "Economics rules"
- During blueprint and validation, AI considers visualization: stories as comic style, case stories as character comics, formulas as metrics/graphs, comparisons as tables/matrices, processes as flowcharts

### What AI Validation Checks
- Text authenticity — are facts correct and traceable
- Image relevance — does the image actually explain the concept
- Coverage completeness — are all planned topics actually covered
- Suggestions — how to improve text, images, or structure
- Missing elements — anything that should be added

### Subject-Specific Checks in Final Validation

| Content Type Present | What AI Checks |
|---|---|
| Economics concepts | Key metrics covered, India data included, recent policy changes |
| Polity/Constitutional | Articles referenced, landmark judgments with both sides (plea + facts + verdict), amendments |
| Historical content | Timeline completeness, cause-effect chains, period coverage |
| Geography content | Locations mapped, neighboring context, physical + political balance |
| CS/Programming | Complexity analysis, edge cases, code examples |
| Medical/Science | Anatomy diagrams, symptom-diagnosis-treatment chain, latest guidelines |
| Any content | Coverage completeness, factual consistency, source traceability |

## PART 8: ERROR HANDLING — UNIVERSAL

Everywhere in the app where AI is called, the same error handling applies:
1. Step 1: AI call is made
2. Step 2: If it fails — auto-retry (wait 2 seconds)
3. Step 3: If it fails again — auto-retry (wait 4 seconds)
4. Step 4: If it still fails — show popup

Error popup contains:
- Failed action name
- Reason (error details)
- Failed prompt (visible in editable textarea)
- Buttons: Try Again, Retry with Simplified Prompt, Retry with Edited Prompt, Skip This Step, Cancel

Smart detection:
- If error contains "context", "token", "length", "limit" → highlight Simplified Retry button
- If error is "rate limit" → auto-wait 30 seconds before showing popup
- If error is "network" → auto-retry when connection returns

This applies to: text generation, image generation, current affairs search, blueprint generation, AI validation, AI chat responses, any AI interaction anywhere.

## PART 13: PROMPT ARCHITECTURE

### Prompt Chain Flow
- Source Input → Stage 3 Analysis Prompts
- Stage 3 Output → Stage 4 Splitting Prompt
- Stage 4 Output → Stage 5 Blueprint Prompts (per part, parallel)
- Blueprint Output → Stage 7 Text Generation Prompt (per part)
- Blueprint Output → Stage 7 Image Prompt Expansion → Image Generation
- Blueprint Output → Stage 7 CA Search Prompt (with grounding)
- Generated Content → Validation Prompt
- User Selection → Visualize-This Prompt

### Key Principles
- Every prompt is visible, copyable, editable, and regeneratable
- User can see exactly what the AI is being asked
- User can modify the prompt and regenerate
- System prompts shown via toggle (not default view)
- Prompts stored as inline JavaScript constants following DEFAULT_PROMPTS pattern
- Users can only edit final generated prompts, not base templates

## PART 16: ALL ARCHITECTURAL DECISIONS

### Decision Q1.1 — Method 2: AI Draft Text Type
Decision: AI generates full comprehensive notes. AI first fetches related sub-topics, then generates content prompt, then generates actual content. Content flows into Method 3 paste area as if uploaded.

### Decision Q1.2 — AI Draft Length
Decision: Medium by default (~10-15 pages, ~8000 words). Option for comprehensive. Option to search internet for that topic. Option to include current affairs for that topic.

### Decision Q1.3 — Sub-topic Structure
Decision: Option B — AI uses sub-topics as foundation but can add more sections it thinks are needed.

### Decision Q1.4 — Generated Text Destination
Decision: Option A — Into Method 3 paste area for user editing before continuing.

### Decision Q2.1 — File Extraction Method
Decision: Technical extraction first (no AI). If fails, auto-failover to AI cleanup. If that fails, auto-failover to AI restructuring. User can also manually choose method A, B, or C.

### Decision Q2.2 — AI Draft Reading Phase
Decision: Option A — Skip reading phase entirely for AI-generated text.

### Decision Q2.3 — Paste Text Cleanup
Decision: Option A — Take as-is, no cleanup.

### Decision Q3.1 — Analysis Architecture
Decision: Hybrid — 3 Prompts + Smart Routing.
- Prompt 1: Subject Detection (fast, 5-10s) — returns subject, sub-discipline, content signals, confidence per signal as JSON
- Prompt 2: Deep Extraction (15-20s) — extracts all topics, definitions, formulas, PYQs, comparisons, examples, timelines, tables as structured JSON
- Prompt 3: Smart Bundle Detection (15-30s) — based on Prompt 1 signals, only runs relevant bundle detection prompts in parallel. Skips irrelevant bundles. User can force-enable skipped ones later.

### Decision Q3.2 — Feature Bundle Auto-Selection
Decision: Three-tier display on Screen 3.
- Auto-enabled (green checkmark, on by default) — high confidence
- Suggested (visible, unchecked, "AI found this but wasn't sure") — medium confidence
- Force-enable (hidden behind "Show more options") — not detected

### Decision Q3.3 — Confidence Display
Decision: Visual icons, no percentages.
- Green dot = strong signals (auto-on)
- Yellow dot = weak signals (suggested)
- Grey dot = not detected (force-enable available)
- Hover tooltip shows reasoning: "Detected 12 place names, 5 historical events"

### Decision Q3.4 — Location Extraction
Decision: Check all facts related to that place WITH RESPECT TO the topic being studied. If place is in current affairs, include those facts. If a country, include map with neighboring countries, their capitals, popular seas or passages. Context-driven facts — not fixed count. Historical topic gets historical facts. Geopolitics gets political facts. Economics gets economic data. Basic detection on Screen 3, deep facts fetched on Screen 7 when part generates. Results cached.

### Decision Q3.5 — Formula Extraction
Decision: Split — Detect formula in Screen 3 (identify, extract variables, note page reference). Deep operations in Screen 7 (derivation, facts, variable deep dive, substitution examples, edge cases, real-world applications, common mistakes).

### Decision Q3.6 — Personality Extraction
Decision: All important facts related to PSC and current affairs. Prompt specifically asks for PSC/UPSC relevant facts about that person. Not generic bio — focused, exam-relevant information. Name + role detected on Screen 3. Full PSC-relevant facts fetched on Screen 7. Cached for reuse.

### Decision Q4.1 — Part Splitting Logic
Decision: Rules as guardrails, coherence first, user final say.
- AI calculates range from page-count table
- AI applies splitting rules (never split formula from explanation, PYQs stay with topic, conceptual coherence)
- AI proposes N parts within range
- User can add/merge/edit on Screen 4
- If AI wants to go outside table range, show warning

Part Count Table:
| Total Pages | Parts Range |
|---|---|
| 1-10 | 1-3 parts |
| 11-20 | 2-6 parts |
| 21-30 | 4-8 parts |
| 31-50 | 5-10 parts |
| 51-100 | 8-15 parts |
| 101-200 | 12-20 parts |

### Decision Q4.2 — Splitting Prompt Inputs
Decision: Analysis output is primary input. Full text included only if under token limit. If over token limit, send text summary per topic instead.

### Decision Q4.3 — Per-Part Bundle Assignment
Decision: Auto-assign bundles per part with global inheritance + per-part override.
- If user enables a bundle globally on Screen 3, AI auto-includes it in parts where that content exists
- AI auto-assigns based on content (Part 2 has formulas → Formula bundle applies)
- User can override per part on Screen 5 (chip UI on cards) and Screen 6 (add/remove in detail view)

### Decision Q5.1 — Blueprint Generation
Decision: One prompt per part, fired in parallel with 1-second gap between each.

### Decision Q5.2 — Blueprint Sections
Decision: One prompt per part produces all 5 sections: headings, text_plan, image_plan, ca_plan, validation_plan. Coherent output. User can regenerate individual sections.

### Decision Q5.3 — Image Style Selection
Decision: AI smart defaults based on content type. User override via dropdown (35 styles). Hover shows reasoning.

### Decision Q5.4 — CA Search Execution Timing
Decision: Generate search queries during blueprint. Execute on Screen 7 when user clicks or when auto-generate is triggered.

### Decision Q5.5 — Screen 6 AI Chat Modification
Decision: Surgical modification of targeted section only. Lightweight undo for last change. Other sections untouched.

### Decision Q7.1 — Text Generation Inputs
Decision: Sliced inputs — only relevant pages per part.
- Part metadata (title, page range, applied bundles)
- Relevant source text slice (only pages for this part)
- Relevant analysis (formulas and definitions for this part)
- ALL definitions from entire document (shared globally)
- ALL formulas from entire document (shared globally)
- Blueprint plan for this part
- Traceability instruction (tag as SOURCE_BACKED, RESEARCH_REQUIRED, OPTIONAL_ENRICHMENT)

### Decision Q7.2 — Text Generation Output Format
Decision: Properly formatted HTML. Once approved, embedded into the page. Approve Part = auto-approve all text, images, and CA in that part.

### Decision Q7.3 — Image Prompt Expansion
Decision: Auto-expand blueprint description into detailed prompt → generate immediately → show prompt for regeneration. Global setting available to preview prompts before generation (default: off).

### Decision Q7.4 — CA Search Method
Decision: Gemini's built-in grounding/search feature (no external API key). Returns fresh data. Fallback to training data with disclaimer if grounding unavailable.

### Decision Q7.5 — AI Validation System
Decision: Two layers.
- Layer 1: Per-part validation when user clicks Approve Part. 1 combined AI call. Summary + issues + suggestions popup. Options: Cancel, Approve Modifications, Ignore & Approve As-Is.
- Layer 2: Final consolidated validation after all parts approved. Content-driven checks (not rigid subject categories). Suggestions to add new parts or enrich existing ones.

### Decision Q7.6 — Refinement Chat
Decision: Smart scope detection. AI infers what sections a natural language instruction affects. Diff preview before applying. Options: Apply All, Apply Selective, Discard, Expand Scope. Full regen requires confirmation with cost warning.

### Decision Q7.7 — Highlight-to-Visualize
Decision: Full contextual awareness — selected text + parent paragraph + part metadata (bundles, subject). AI recommends 3 styles from 35-style catalog with reasoning. Cross-paragraph selection uses all highlighted content + surrounding paragraphs as context.

### Decision Q7.8 — Add New Part
Decision: Quick blueprint with optional edit. Modal shows topic input + sub-topics. Two buttons: Generate Immediately (auto-blueprint with defaults) or Configure Blueprint First (edit before generating). CA auto-decision based on global toggle or topic sensitivity.

### Decision Q8.1 — Export
Decision: No AI in export. Already validated. Pure formatting: compile approved parts with embedded text and images. Copy formatted text + images. Save as PDF.

### Decision QX.1 — Error Handling
Decision: Combined popup with all recovery options. Show failed prompt (editable). Buttons: Retry As-Is, Retry Simplified, Retry with Edited Prompt, Skip, Cancel. Smart detection for error type.

### Decision QX.2 — Token/Context Limits
Decision: Semantic chunking at natural boundaries (chapter > section > page). Each chunk gets context (previous summary, next preview). Analyze chunks separately. Merge analyses (union topics, deduplicate, concatenate). Parts can span original chunks.

### Decision QX.3 — Prompt Visibility
Decision: Show user prompt by default. Toggle to see system prompt. Both visible for full transparency. User can edit user prompt and regenerate.

## PART 17: FINAL CLARIFYING DECISIONS (Sections A-K)

### Decision QA.1 — Method 2 Multi-Step Chain
Decision: Confirmed 5-step chain.
1. User types topic + sub-topics
2. AI fetches/expands related sub-topics
3. Expanded list shown to user for approval/editing
4. After approval, AI generates full content
5. Content appears in Method 3 paste area

### Decision QA.2 — Expanded Sub-Topics Visibility
Decision: Show expanded list to user. User approves/edits before content generation. User can uncheck items, add own sub-topics. Panel appears below Method 2 inputs.

### Decision QA.3 — Internet Search Timing for Method 2
Decision: Both prompts use internet search when toggle is ON. Sub-topic expansion searches for latest developments and new sub-topics. Content generation searches for current facts and data while writing.

### Decision QB.1 — Location Deep Facts Timing
Decision: Screen 7 only. Basic detection on Screen 3 (name, count, page refs). Deep facts fetched during generation. Saves cost if part is removed. Results cached.

### Decision QB.2 — Facts Per Location
Decision: Context-driven, not fixed count.
- Indus Valley topic + MP → archaeological sites, historical significance, ancient trade routes
- Geopolitics + MP → borders, strategic locations, security, political geography
- Current Affairs + MP → recent schemes, budget, elections, development
- Economics + MP → GSDP, per capita income, key industries, poverty index
- Geography + MP → rivers, mountains, climate, minerals
- Passing mention → basic only (capital, region, 1-2 relevant facts)

Dynamic prompt template includes content context and explicitly says DO NOT extract unrelated facts.

### Decision QB.3 — International Location Treatment
Decision: Same context-driven approach as domestic. India-angle comes naturally because source content is from Indian perspective. No hardcoded rules for international vs domestic.

### Decision QC.1 — New Image Suggestion Timing
Decision: All three moments via unified function chain.
- During text generation: AI includes IMAGE_NEEDED tags
- After text generation: AI reviews and suggests
- During validation: AI finds gaps and suggests with position
Same function chain handles all three triggers.

### Decision QC.2 — Mixed-Style Images

#### Screen 2: Reading

What Happens Behind The Scenes:

For File Upload:
1. Detect file type
2. Extract text from file (PDF: page by page, Images inside PDF: OCR, DOC/DOCX: parse structure, TXT/MD: read directly, HTML: strip tags keep content, JPG/PNG: full OCR)
3. Clean up junk (remove watermarks, page numbers, repeated headers/footers, text shorter than 10 characters)
4. Organize in reading order (sort top to bottom per page, merge text and image-extracted text, maintain page references)
5. If extraction fails: auto-failover to AI cleanup, then AI restructuring

For Topic Name (Method 2):
1. AI generates comprehensive content on the topic (multi-step chain)
2. Content includes definitions, examples, comparisons, data
3. Structured with clear headings
4. Treated as if it were an uploaded document

For Pasted Text:
1. Take text as-is
2. Try to detect structure (headings, lists)
3. Treat as single-page document

- Each step shows checkmark when complete
- Progress bar moves smoothly
- No user action needed
- Auto-advances to Screen 3 when done

#### Screen 3: Understanding + Feature Detection

What AI Analyzes:
The AI reads ALL extracted text and produces a comprehensive understanding using 3-prompt hybrid approach.

Prompt 1 — Subject Detection (5-10 seconds):
Detects primary subject, sub-discipline, content signals (formulas, dates, code, locations, persons, legal refs, diagrams), confidence per signal. Returns JSON.

Prompt 2 — Deep Extraction (15-20 seconds):
Given the detected subject, extracts all topics with page refs, definitions with IDs, formulas with variables, PYQs with year/type, comparisons, examples, timelines, tables. Returns structured JSON.

Prompt 3 — Smart Bundle Detection (15-30 seconds):
Based on Prompt 1 signals, only runs detection for relevant bundles. Skips irrelevant ones. 6 relevant bundles run in parallel or as one combined prompt.

Feature Detection Display:
After analysis, the app shows detected features as toggleable items with three-tier system:
- Green checkmark: auto-enabled (high confidence)
- Yellow/unchecked: suggested (medium confidence)

## PART 25: TOKEN/CONTEXT LIMIT HANDLING

When source text exceeds model context window:
1. Detect: If token count exceeds 80% of model limit, trigger chunking
2. Split at natural boundaries: Chapter headings first, then section headings, then page boundaries
3. Each chunk gets continuity context: chunk_id, section_boundaries, previous_chunk_summary, next_chunk_preview
4. Analyze each chunk through Stage 1/2/3 pipeline separately
5. Merge analyses: Union all topics, deduplicate definitions/formulas by content, concatenate PYQs
6. Stage 4 splitting works on merged analysis — parts can span original chunks

If even one section is too large for single call:
- Fall back to sub-section chunking (paragraph groups)
- Warning to user: "Very large section detected — analysis may have reduced granularity"

## PART 26: SLICED INPUT STRATEGY FOR TEXT GENERATION

When generating notes for a specific part (e.g., Part 2, pages 6-10):

What is included in the prompt:
- Part metadata: title, page range, applied bundles
- Source text slice: ONLY text from pages 6-10
- Part-specific analysis: topics, examples, timelines, PYQs, comparisons from pages 6-10
- ALL definitions from entire document (global share)
- ALL formulas from entire document (global share)
- Blueprint plan for this part
- Traceability instruction

Why definitions and formulas are shared globally:
- They are small in data size (few KB total)
- They might be referenced across any part
- Prevents "definition not found" errors
- Token cost increase is minimal

Why other elements are strictly per-part:
- PYQs, examples, timelines, comparisons are part-specific by nature
- Including all would waste tokens without quality benefit

Cross-part formula references:
- If Part 2 references a formula from Part 3, the structured formula JSON data is included
- AI arranges appropriately in the output
