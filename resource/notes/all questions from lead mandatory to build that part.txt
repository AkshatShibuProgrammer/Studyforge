### **Q3.1 — Analysis Prompt Architecture: How many AI calls to analyze content?**

**Question:** The app needs to detect subject, topics, definitions, formulas, PYQs, locations, personalities, charts, institutions, and more (~130 sub-features across 12 bundles). Should this be ONE prompt, TWO prompts, or MULTIPLE prompts?

**Options Explored:**

**Option A: ONE Mega-Prompt**
- Single AI call detects everything
- Pros: Fastest, cheapest, simplest
- Cons: AI attention dilutes when detecting 130 things at once. Accuracy drops ~40% with >20 targets. Hallucination risk (AI invents features). If call fails, entire analysis restarts.

**Option B: TWO Prompts (Basic + Advanced)**
- First call detects subject + basics, second detects bundles
- Pros: Second prompt is smarter (knows subject). Better accuracy than A.
- Cons: Second prompt still asks for 130 things (still diluted).

**Option C: 12 Prompts (One Per Bundle)**
- One prompt per bundle category (12 separate calls)
- Pros: Highest accuracy (each focused on 10-15 sub-features). Can run in parallel.
- Cons: Highest token cost (sends source 12 times). Complex to implement. Wasteful for narrow content (CS textbook doesn't need Medical/Legal prompts).

**Option D: Hybrid — 3 Prompts + Smart Routing**
- Prompt 1: Subject Detection (fast, 5-10s)
- Prompt 2: Deep Extraction (definitions, formulas, PYQs — 15-20s)
- Prompt 3: Smart Bundle Detection (only relevant bundles, 15-30s)

**Lead's Decision:** Option D — Hybrid (3 Prompts + Smart Routing)

**How It Works in Detail:**

**Prompt 1 — Subject Detection (5-10 seconds):**
```
"Read this content and return ONLY:
- Primary subject (Economics/CS/Medicine/Literature/Law/etc.)
- Sub-discipline
- Content signals detected (does it have: formulas? dates? 
  code? locations? persons? legal refs? diagrams?)
- Confidence score per signal
Return as JSON."
```

**Prompt 2 — Deep Extraction (15-20 seconds):**
```
"Given this is [Economics/Macroeconomics] content, extract:
- All topics (with page refs)
- All definitions (with IDs)
- All formulas (with variables)
- All PYQs (with year/type)
- All comparisons
- All examples
- All timelines
- All tables
Return structured JSON."
```

**Prompt 3 — Smart Bundle Detection (15-30 seconds):**
Based on Prompt 1's content signals, ONLY fire prompts for bundles that are relevant.

Example for Economics PDF:
- Signals detected: formulas ✓, personalities ✓, data/charts ✓, administration ✓, historical ✓
- Bundles to detect: Formula Ops, Personalities, Chart/Data, Administration, Historical, Storytelling (6 bundles)
- Skip: Geography (no locations), Legal (no laws), Medical, Scientific, CS
- Fire 6 parallel prompts (or one combined prompt for 6 relevant bundles)

**Why This Was Chosen:**
- Best accuracy without token waste
- Smart routing means irrelevant bundles don't run
- Parallel execution keeps it fast (~40s total instead of 3-6 minutes)
- User sees 3 clean prompts (not 12)
- Force-enable still works — if user wants Geography for Economics content, they toggle it on → triggers on-demand Geography prompt
- Failure recovery — if one bundle fails, retry only that bundle

**Sub-decisions made:**
- Signal → bundle routing is **rule-based** (deterministic, fast, easy to debug)
- When user force-enables a hidden bundle, it fires a **new prompt for that bundle only**
- Prompt 3 bundles sent as **one combined prompt for relevant bundles** (cheaper for MVP, upgrade to parallel individual later if accuracy issues arise)
- Prompt visibility UI: **Accordion on Screen 3**, collapsed by default

### **QX.2 — Token/context limits: When source text is too long for one AI call**

**Question:** What if a 500-page PDF exceeds Gemini's context window?

**Options Explored:**

**Option A: Chunk text, send multiple calls, merge** — Quality but complex
**Option B: Summarize first, analyze summary** — Fast but loses detail
**Option C: Send important sections, skip rest** — Loses content
**Option D: Semantic chunking at natural boundaries + structured merge** — Best quality

**Lead's Decision:** Option D — Semantic Chunking + Structured Merge

**How It Works:**
1. **Detect:** If token count > 80% of model limit → trigger chunking
2. **Split at natural boundaries:** Chapter headings > Section headings > Page boundaries (in order of preference)
3. **Each chunk gets context:** `{chunk_id, section_boundaries, previous_chunk_summary, next_chunk_preview}` for continuity
4. **Analyze each chunk** through Stage 1/2/3 pipeline separately
5. **Merge analyses:** Union topics, deduplicate definitions/formulas by content, concatenate PYQs
6. **Stage 4 splitting** then works on merged analysis (parts can span original chunks)

**Sub-decision:** If even one section is too large for a single call:
- Fall back to sub-section chunking (paragraph groups)
- Warning to user: "Very large section detected — analysis may have reduced granularity"
